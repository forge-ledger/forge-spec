# 0004 · 新鲜度只挂在 state 上

## 问题

哪些资产会"过期"？如果给所有类型都加过期时间，会发生什么？

## 考虑过的选项

1. **所有类型都带新鲜度**：规则统一，但会给不会过期的东西制造检查项。
2. **只给 state 带新鲜度**：它与现实绑定，过期是真实失败模式。
3. **不做过期检查**：库会慢慢腐烂，而没有任何信号。

## 选定

只给 `state` 带新鲜度，默认窗口 30 天。

- `decision` 一旦 `accepted` 不可变；"过期"对它没有意义。
- `event` 是发生过的事，更不会过期。
- `rule` 靠 `origin_incident` 溯源而不靠时间。

新鲜度检查**不放进提交检查**：它的判据依赖"今天"，会让一份没动过的资产
在某天早上突然变红。它属于维护任务。

## 后果

- **好**：过期信号有明确归属；不会被其他类型的噪音淹没。
- **代价**：`state` 必须多两个字段：`last_confirmed` 与 `subject`。
- **残余风险**：自动确认会让库永远看起来新鲜；因此规范明确禁止自动确认。
