# 出处与新鲜度规则

> 本文档定义 span 的语法、解析规则与判定结果的分工。

## Span 语法

```
span   := scheme "://" target [ "#" anchor ]
scheme := "file" | "src"
anchor := "h:" 标题 | "t:" 原文片段 | "k:" 键路径 | "L<起>-L<止>"
```

- `file://` —— 工作区/仓库内的文件。规范仓库的示例全部使用这一种。
- `src://` —— `sources/` 层里的来源。需要实现提供结构化来源解析。
- 比较前把空白折叠成单个空格：文档里被引用的句子经常跨行，按字节比较会让
  改一次排版就废掉所有引用——那不是"出处是硬约束"，是"出处是脆弱的字符串比对"。

### 四种锚点

| 锚点 | 指向 | 判据 |
|---|---|---|
| `#h:标题` | 一个 ATX 标题 | 目标文件里有标题归一化后相等 |
| `#t:原文片段` | 一段原文（≥ 8 字符） | 目标文件归一化后**包含**它 |
| `#k:键路径` | 结构化来源里的一条记录（`conv_01/msg_03`） | 由来源连接器解析后确认键存在 |
| `#L12-L20` | 行区间（1 基、闭区间） | 目标文件有那么多行 |

`#t:` 的下限 8 字符不是随手定的：太短的片段在任何文档里都能命中，
它会让检查**通过**，但那不是证据。写 `#t:` 时还要注意别把锚点切在
Markdown 强调符号中间：`**这段**` 归一化后仍是 `**这段**`，所以 `#t:这段`
不命中——锚点要指向文档里本来就有的连续文字。

`#k:` 是 v1 里唯一的**结构化**锚点。`#t:` 在 JSON 上会脆断，因为导出把引号、
反斜杠、换行转义成 `\"`、`\\`、`\n`，同一句话在原文与原始字节里是两个不同的字符串。

## 两条不能让步的规则

1. **没有出处的断言不许进 `assets/`。** 出处是硬约束，不是元数据奢侈品。
2. **外部证据先落进 `sources/`，再用 `src://` 引用。** URL、工单、线上日志不能
   直接当 span：出处会随外部世界腐烂，而**腐烂的出处比没有出处更糟**——
   它看起来像证据。

## 判定结果

判定的输出是红/绿，每个码对应一种修法。合并码等于合并修法。

| 码 | 含义 | 修法 |
|---|---|---|
| `ASSET_FRONTMATTER_INVALID` | front-matter 不合法（缺字段、类型错、值域外） | 补全 front-matter；字段表见 `../schema/taxonomy.yaml` |
| `SCHEMA_VERSION_MISMATCH` | `schema_version` 与分类法版本不一致 | 跑迁移通道；不要在检查器里顺手兼容 |
| `ID_PREFIX_MISMATCH` | ID 的类型前缀与 `type` 字段不一致 | 改成同一个类型；前缀表见 `ids.md` |
| `PROV_NO_SOURCES` | 没有 `sources`：断言没有出处 | 补上 span |
| `PROV_SPAN_UNRESOLVED` | span 语法不合法，或目标/锚点解析不到 | 去修 span：改掉被引用的原文，或指向仍然存在的那一处 |
| `PROV_SCHEME_UNAVAILABLE` | 本宿主无法校验这个 scheme（例如没有 `sources/`） | **这是「无法校验」，不是「通过」**；换 scheme，或到能校验它的宿主里跑 |
| `REQUIRED_FIELD_MISSING` | 类型要求的字段缺失或为空 | 补上；要求写在分类法里，不在文档里 |
| `REQUIRED_SECTION_MISSING` | 类型要求的正文章节缺失 | 按 `../schema/asset-types/<类型>.md` 的模板补 |
| `FRESHNESS_EXPIRED` | `state` 超过新鲜度窗口未确认 | 确认是否仍成立；仍成立就更新 `last_confirmed` |

`PROV_NO_SOURCES` 与 `PROV_SPAN_UNRESOLVED` **必须是两个码**：两者的修法不同
（去补证据 vs. 去修 span）。合并成一个码，输出就从"行动指令"退化成了"报了个错"。
`PROV_SCHEME_UNAVAILABLE` 单独存在的理由更硬：**"无法校验"和"校验通过"
必须是两种不同的输出。**

## 出处是**重建**的，不是照抄的

实现不应把模型或人工写的出处字符串原样存下来：逐条解析，只留能解析的那些，
再用统一的格式重新拼一遍。理由：资产里的 `sources` 与索引里的键必须是同一个字符串；
差一个空格，查不到，而且是静默查不到。重建顺带做掉去重与排序
（同一处证据说两遍不算两处；顺序要确定）。

大小写变体（`SRC_xxx`）**不在**重建之列：目标的比较是逐字节的，
它会被当成编造的出处丢掉。这是有意的——"大小写不同但看着像"
正是需要人看一眼的那类东西，静默归一化会让它消失。

## 新鲜度只挂在 state 上

- `state` 会过期，所以要 `last_confirmed` + 窗口（默认 30 天）。
- `decision` 一旦 `accepted` 不可变；`event` 是发生过的事；`rule` 靠
  `origin_incident` 溯源而不靠时间。给它们定过期时间只会制造一个没有内容的
  检查项，而没内容的检查项会被跳过。
- **新鲜度检查故意不在提交检查里**：它的判据必须只依赖输入，而新鲜度依赖"今天"。
  把时钟塞进检查，会让一份没动过的资产在某天早上突然变红，而红的原因是
  "时间过去了"——那是维护任务的职责，应单独运行。
- 实现不得提供"自动确认"：自动刷新会让库永远看起来新鲜。
