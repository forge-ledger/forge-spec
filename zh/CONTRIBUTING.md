# 贡献指南

感谢你考虑贡献。本规范的目标是稳定、可校验、可迁移；贡献也按这个标准衡量。

## 可以贡献什么

- 规范文本的澄清与错字修正；
- 新的**合成**示例（必须能被 `node validate.mjs` 校验）；
- 校验规则的补充与反例；
- 兼容性反馈：某个真实实现读不懂哪一条规则。

## 不要贡献什么

- **真实会话、客户数据或任何"脱敏样例"。** 一次误提交就是一次信任崩塌。
- 评测集、打分阈值或用于给某个实现打分的用例。
- 路线图日期或"下个季度会做"的承诺。
- 只为某个实现服务的私有扩展；规范必须保持实现中立。

## 提交前

```bash
node validate.mjs
```

要求：

- 所有示例通过校验；
- 新增示例必须引用 `../examples/sources/` 里真实存在的合成句子；
- 修改规范文本时，同步检查 `../schema/taxonomy.yaml`、`../schema.json` 与示例是否仍然一致；
- 提交信息使用 DCO 签名：`git commit -s`。CI 的 `dco` job 会检查每个提交；
  没有 `Signed-off-by` 的 PR 不会变绿。
- 如果通过 GitHub 网页编辑文件，请在提交信息末尾手动加一行：
  `Signed-off-by: 你的名字 <你的邮箱>`。

## 许可

- 规范文本、分类法与示例按 **CC0-1.0** 贡献；
- 文档按 **CC-BY-4.0** 贡献。

提交即表示你同意按对应许可发布你的贡献。

## Pull Request 检查清单

- [ ] 变更属于当前版本，或已按 `GOVERNANCE.md` 发起 RFC；
- [ ] 示例是合成的，不含任何真实数据；
- [ ] `node validate.mjs` 通过；
- [ ] 如果改了字段或语义，`CHANGELOG.md` 有对应说明；
- [ ] 提交带 `Signed-off-by`（`git commit -s`）。

## 行为准则

参与本项目即表示同意遵守 `CODE_OF_CONDUCT.md`。
